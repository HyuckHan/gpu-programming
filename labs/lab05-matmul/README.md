# lab05 — 행렬곱 (naive)

**목표:** 스레드 하나가 결과 행렬의 원소 하나를 맡는 가장 단순한 행렬곱 커널을 직접 작성한다.

> **lab06 에서 이 커널을 기준선으로 삼아 공유 메모리 타일링과 비교한다.**
> 측정한 GFLOP/s를 반드시 보고서에 남겨 두어라.

## 과제

`matmul.cu`의 `mm_kernel` 본체를 채운다. 채울 곳은 그곳 하나뿐이고, 시그니처,
실행 구성, 호스트 코드, 검증은 이미 완성되어 있다.

3장 슬라이드 22의 코드를 그대로 옮기면 된다. 변수명(`row`, `col`, `sum`, `i`,
`N`)도 슬라이드와 같게 유지하라.

> N이 `blockDim`의 배수인 경우만 다루므로 경계 검사는 필요 없다
> (배수가 아니면 프로그램이 실행 전에 막는다).
> 행렬은 정사각(N×N)으로 단순화했다.

## 빌드와 실행

```
make            # matmul 을 빌드한다
make run        # ./matmul 4096 16 과 같다
make help       # 쓸 수 있는 명령과 인자를 모두 보여준다
```

인자는 `./matmul <N> <blockDim>` 형태다. `blockDim`은 8, 16, 32 중 하나이고
N은 그 배수여야 한다. 인자를 생략하면 N=4096, blockDim=16이다.
블록은 `blockDim x blockDim`의 2차원이므로 32면 한 블록에 1024 스레드다.

```
./matmul 4096 16      # 기본 조건
./matmul 1024 16      # 행렬이 작아지는 조건
./matmul 4096 32
```

프로그램이 첫 두 줄에 행렬 3개의 합계 크기와 **이 GPU 의 L2 크기**를 찍고,
합계가 L2 안에 들어가는지 아닌지까지 판정해 준다. L2 는 카드마다 다르므로
README 에 숫자를 적지 않는다. 두 `N` 에서 그 판정이 어떻게 달라지는지 보라.

`make run N=1024 B=32` 처럼 Makefile 변수로 넘겨도 된다.
nvcc 플래그는 Makefile이 관리하므로 직접 칠 일은 없다.

## 검증

```
make test       # python3 verify.py 와 같다
```

`verify.py`가 빌드부터 네 가지 (N, blockDim) 조합 실행까지 자동으로 돌린다.
실패하면 짚이는 원인까지 알려 준다. **제출 전에 반드시 통과시켜라.**

검증 방식은 N에 따라 두 가지다.

- **N ≤ 1024** — CPU 참조 구현(`mm_cpu`)으로 전체를 다시 계산해 전부 대조한다.
- **N > 1024** — 무작위로 고른 원소 4096개만 CPU로 직접 계산해 대조한다.
  CPU 행렬곱은 O(N³)이라 N=2048에서 이미 1분을 넘고 N=4096이면 실습 시간 안에
  끝나지 않는다.

부동소수점 덧셈 순서가 달라 값이 미세하게 어긋나는 것은 정상이므로,
행렬 전체의 대표 크기 대비 상대오차 1e-3까지는 통과로 친다.

## blockDim 스윕

`./matmul 4096 <blockDim>`을 세 번 돌려 표를 채운다.

| blockDim | 블록당 스레드 | ms | GFLOP/s |
|---|---|---|---|
| 8 | 64 |  |  |
| 16 | 256 |  |  |
| 32 | 1024 |  |  |

**`blockDim=32` 행은 따로 표시해 두어라.** lab06 의 타일링 실습은 32×32 블록으로
돌아가므로, 그 행이 타일링과 직접 비교할 수 있는 기준선이다.
