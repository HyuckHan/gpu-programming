# lab11 — 리덕션 5단계 최적화 사다리

**목표:** 같은 합을 구하는 커널을 다섯 번 고쳐 가며 유효 대역폭이 어디까지 오르는지 재고, 그 과정에서 부동소수점 덧셈이 순서에 좌우된다는 것을 확인한다.

## 실습 순서

```

./assoc

세 줄이 출력된다. 두 번째와 세 번째 줄을 비교하라.

토론 문제를 풀 때 근거로 쓸 수 있는 관찰 도구가 하나 더 있다. 필요할 때 돌려 보라.

```

## 2. 다섯 커널을 재 본다

```
make
./reduce
```

프로그램이 먼저 CPU 합 두 개를 찍는다. 하나는 `float`로, 하나는 `double`로
더한 것이고 **더한 순서는 둘 다 앞에서 뒤로 같다.** 그다음 다섯 커널의 합과
성능이 나온다.

이 시점에서 `shared`와 `coarsened`는 `(미구현)`으로 나온다. 아직 안 채웠으니 정상이다.

## 3. 표를 채운다

아래 표에 **다섯 커널 모두** 적는다. 검증 열도 나온 그대로 적는다.

| 버전 | ms | GB/s | 이론 대비 | 검증 |
|---|---|---|---|---|
| atomic |  |  |  |  |
| naive |  |  |  |  |
| coalesced |  |  |  |  |
| shared |  |  |  |  |
| coarsened |  |  |  |  |

이론 대역폭은 프로그램이 실행 중인 GPU에서 직접 조회해 첫 줄에 찍는다.

**예상되는 모양은 이렇다.** `atomic`은 나머지와 자릿수가 다르게 느리다.
`naive`에서 `coalesced`로 갈 때 한 번 오르고, `shared`에서 다시 크게 오른다.
그리고 **`shared` 이후로는 이론 대비 85% 근처에서 포화한다.**
`coarsened`가 `shared`보다 빠를 수도, 느릴 수도 있다. 두 값의 차이는
실행할 때마다 순위가 바뀔 만큼 작다. 나온 그대로 적으면 된다.

## 빌드와 실행

```
make            # reduce 만 빌드한다
make assoc      # 워밍업용은 1단계에서 따로 빌드한다
make run        # ./reduce 67108864 과 같다
make clean
make help       # 쓸 수 있는 명령과 인자를 모두 보여준다
```

인자는 `./reduce <N>` 형태이고, 생략하면 `67108864`(2^26, 256MB)다.

> 슬라이드의 커널들에는 경계 검사가 없다. 그래서 **N은 2의 거듭제곱만** 받는다.
> 2048 이상 2^28 이하여야 하고, 아니면 프로그램이 실행 전에 막는다.
> `BLOCK_DIM`은 256, `COARSE_FACTOR`는 4로 고정이다.

`make run N=16777216` 처럼 Makefile 변수로 넘겨도 된다.

## 측정에 대해

`naive`와 `coalesced`는 입력 배열을 **제자리에서 고쳐 쓴다.** 그래서 프로그램은
원본을 디바이스에 따로 하나 보관해 두고, 커널을 돌리기 직전마다 작업 버퍼를
원본으로 되돌린다. 되돌리는 시간과 `sum` 초기화 시간은 측정에 들어가지 않는다.
이 처리를 안 하면 두 번째 커널부터 앞선 커널이 뭉갠 값을 읽어 엉뚱한 합이 나온다.

유효 대역폭은 `N * 4바이트 / 커널 시간`으로 계산한다. 커널마다 한 번씩 예열한
뒤 측정한다.

## 토론 문제

보고서에 답한다. 답을 찾기 전에 1단계의 `./assoc` 출력을 다시 보면 도움이 된다.

**1.** CPU의 `float` 합과 `double` 합이 서로 다르게 나온다. 더한 값도 같고 더한
순서도 같은데 왜 다른가? 둘 중 어느 쪽이 참값에 가까운가? 그렇게 판단한 근거는?

**2.** `naive`에서 `coalesced`로 갈 때 커널 코드는 거의 바뀌지 않았다.
`i`를 구하는 식과 `stride` 루프의 방향뿐이다. 그런데 유효 대역폭은 크게 달라진다.
무엇이 달라진 것인가? 한 워프의 32개 스레드가 각각 어느 주소를 읽는지
두 커널에 대해 각각 적어 보면 보인다.

**3.** `shared`와 `coarsened`의 차이가 거의 없다. 두 번 재면 순위가 뒤집히기도 한다.
`coarsened`는 스레드 하나가 원소를 여덟 개씩 맡아 리덕션 트리의 단계 수를 줄이는데,
그런데도 왜 더 빨라지지 않는가? **무엇이 한계로 작용하고 있는가?**
표의 "이론 대비" 열이 얼마에서 멈추는지 보라. 그 숫자가 답을 가리킨다.

**4.** 다섯 커널 중 `atomic`만 검증에 실패한다. 그런데 다섯 커널 모두 마지막에는
`atomicAdd`로 `sum`에 더한다. 무엇이 다른가? 각 커널이 `sum`에 **몇 번** 더하는지,
그리고 **한 번에 얼마만 한 값**을 더하는지 세어 보면 보인다.
