# lab09 — 컨볼루션과 상수 메모리

**목표:** 필터를 어디에 두는지, 그리고 필터가 얼마나 큰지가 성능에 어떻게 연결되는지 측정한다.

lab03의 blur와 같은 이미지 처리다. 다만 이번에는 가중치가 있는 필터를 쓰고,
그 필터를 **상수 메모리**에 두었을 때와 **전역 메모리**에서 읽을 때를 비교한다.
`pgm.h`는 lab03에서 쓰던 것을 그대로 가져온 것이다.

## FILTER_RADIUS 는 실행 인자가 아니다

`filter_c` 배열의 크기가 컴파일 시점에 정해지므로 `FILTER_RADIUS`는 실행할 때
바꿀 수 없다. 값을 바꾸려면 다시 빌드해야 한다.

```
make RADIUS=4
```

`FILTER_DIM`은 `2*FILTER_RADIUS + 1`이다. 기본값은 `RADIUS=2`, 즉 5x5 필터다.
`./sweep.sh`는 이 재빌드를 자동으로 해 준다.

## 1. 필터 크기 스윕

```
make
./sweep.sh
```

`global ms`와 `비율` 열은 2절을 끝내야 값이 나온다. 지금은 `-`로 나온다.

| RADIUS | FILTER_DIM | 커널 ms | GB/s | GFLOP/s | FLOP/B |
|---|---|---|---|---|---|
| 1 | 3 | | | | |
| 2 | 5 | | | | |
| 4 | 9 | | | | |
| 8 | 17 | | | | |

프로그램은 비율을 두 가지로 찍는다. 기준이 다르니 헷갈리지 말 것.

- **연산/바이트** — 최소 트래픽 기준이다. 출력 픽셀 하나당 입력을 한 번 읽고
  출력을 한 번 쓴다고 본다. 겹쳐 읽는 부분은 캐시가 흡수하라고 있는 것이므로
  세지 않는다. 위 표에 적는 값은 이것이다.
- **슬라이드 20** — 커널이 실제로 요청하는 전역 접근을 그대로 센다.
  탭마다 입력을 한 번씩 읽는 것으로 계산한다. 교재가 말하는 그 비율이다.

## 2. conv_global.cu 의 TODO 채우기

`conv_global.cu`는 같은 커널을 **필터만 전역 메모리에서 읽도록** 바꾼 것이다.
이 파일에는 상수 메모리 선언이 없고, 필터가 커널 매개변수로 들어온다.

커널 시그니처와 호스트 쪽 `cudaMalloc`, `cudaMemcpy`는 이미 완성되어 있다.
채울 곳은 커널 안의 곱셈 한 자리뿐이다. 지금은 `1.0f`가 들어가 있다.

`filter`는 1차원 배열이다. `filterRow`와 `filterCol`을 하나의 인덱스로 합쳐야 한다.

채운 뒤 확인한다.

```
make
./conv_global
make test
```

## 빌드와 실행

```
make               # conv_const 와 conv_global 을 빌드한다
make RADIUS=4      # FILTER_RADIUS 를 4로 두고 다시 빌드한다
make run           # ./conv_const 4096 4096 과 같다
make test          # verify.py 로 자체 점검한다
make clean
make help
```

인자는 `./conv_const <width> <height>` 형태이고, 생략하면 `4096 4096`이다.
작업 디렉터리에 `input.pgm`(8비트 회색조 P5)이 있으면 그것을 읽고, 없으면
lab03과 같은 합성 사선 무늬를 만들어 쓴다. 결과는 `out.pgm`으로 저장된다.

이 디렉터리에는 `pgm.h`와 `common.cuh`가 함께 들어 있어야 한다.
없으면 `make`가 어디서 복사해 오라고 알려주고 멈춘다.

## 검증

```
make test
```

`verify.py`는 **conv_global 만** 판정한다. `conv_const`는 완성 상태로 제공된
것이라 판정 대상이 아니다. `FILTER_RADIUS`를 바꿔가며 다시 빌드하고,
정사각이 아닌 이미지 크기도 함께 확인한다.

프로그램 자체는 이미지가 작으면 CPU 참조 구현으로 전체를 다시 계산해 대조하고,
크면 무작위로 고른 픽셀만 대조한다. 컨볼루션도 O(width x height x FILTER_DIM^2)이라
큰 이미지에서 전체를 CPU로 계산하면 너무 오래 걸린다.

## 토론 문제

**1.** `FILTER_RADIUS`가 커지면 FLOP/B가 어떻게 변하는가?
1절 표의 GB/s 열과 GFLOP/s 열이 각각 어느 방향으로 움직이는지 함께 보라.
이 커널은 메모리에 묶여 있는가, 연산에 묶여 있는가?
`RADIUS=1`일 때와 `RADIUS=8`일 때의 답이 같은가?

**2.** 상수 메모리와 전역 메모리의 차이가 예상보다 작게 나올 수 있다.
3절 표에서 실제로 몇 배가 나왔는지 적고, 그 크기를 설명하라.
작은 필터일 때 한 워프의 32개 스레드가 필터의 어느 값을 읽는지 생각해 보면
실마리가 잡힌다. 그 값이 이미 어디에 들어가 있겠는가?

**3.** 필터가 커질수록 두 버전의 차이는 커지는가 작아지는가? 왜인가?
필터 전체가 몇 바이트인지 `RADIUS=1`과 `RADIUS=8`에 대해 각각 계산해 보라.
