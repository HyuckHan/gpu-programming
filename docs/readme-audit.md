**[E·권장] sanitizer 2단계의 대비가 글로 적혀 있지 않다 — README.md:43~53**

> **(나)** `vecadd_naive.cu`에서 `numBlocks`를 구하는 줄을 **올림으로 고쳐서**
> 다시 빌드하고 돌려 보라. (…) `compute-sanitizer ./vecadd_naive 999999 256`

순서 자체는 맞다. 내림 상태(`vecadd_naive.cu:42`)에서는 범위 밖 접근이 아니라
미실행이므로 sanitizer 가 0건을 보고하고, 올림으로 고치면 `999999 / 256` →
3907 블록 → 1000192 스레드가 되어 진짜 범위 밖 쓰기가 생긴다. 문제는 README 가
**0건이 나오는 쪽을 아예 돌려 보게 하지 않는다**는 것이다. 도구가 아무것도
못 잡는 경우를 보지 않으면 "도구를 돌렸는데 조용하다"는 상황을 해석할 수 없다.
또 올림으로 고치면 `검증`은 PASS 로 바뀌는데(범위 밖 쓰기가 cudaMalloc 여유
공간에 떨어진다) sanitizer 는 오류를 보고한다. 이 어긋남이 이 단계의 핵심인데
README 에 예고가 없다.
수정 방향: (나)를 두 번 돌리게 한다. ① 고치기 전 sanitizer → 0건,
② 올림으로 고친 뒤 sanitizer → 오류 발생, 그런데 `검증`은 PASS.
두 결과를 나란히 적게 한다.

| | 4060 Ti | 5060 |

**[C·권장] 출력/스레드 비율과 GB/s 의 연결이 단조롭지 않다 — README.md:92~95, 178~179**

수정 방향: "비율만으로는 설명되지 않는 지점이 있다. 블록당 스레드 수도 함께
